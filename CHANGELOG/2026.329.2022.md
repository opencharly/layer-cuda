# 2026.329.2022 — fix(cuda): the absence assertion counts the vdpau DRIVER file, not the tree

## Summary

The merged absence assertion (opencharly/layer-cuda#41) counted the **`/usr/lib/vdpau` directory's
existence** as driver user-space. But the generic libvdpau — pulled by `ffmpeg`, which this layer
requires — ships `/usr/lib/vdpau/libvdpau_trace.so`, so the first real composition of `layer-cuda` +
`layer-cdi` reds on a **clean** image:

```
#14 0.101 cuda: driver user-space baked (libraries, binaries or trees): 2 item(s)
```

Changed, in full:

- `charly.yml`: the vdpau arm counts **`libvdpau_nvidia*`** (the driver file), not the tree; the
  `nvidia` tree keeps its whole-content check; the step takes `CUDA_LIB_DIRS` / `CUDA_BIN_DIRS` and
  carries `id: cuda-no-baked-driver`, so it can be executed against a fixture.
- `tests/no-baked-driver.sh`: **added**. It awk-extracts the SHIPPED step body and runs it against a
  synthetic layout — a clean tree must pass, a planted `libvdpau_nvidia.so.1` must red. It executes
  the shipped predicate (no copy), so a revert to `[ -e "$d/vdpau" ]` fails it.
- `tests/strip-runtime-survives.sh`: **deleted** — the control for the strip #41 removed.
