# 2026.320.1929 — fix(arch): drop the opencl-nvidia driver library the cuda package pulls in

## Summary

Arch's `cuda` package depends on **`opencl-nvidia`**, which ships the NVIDIA OpenCL
driver library — `/usr/lib/libnvidia-opencl.so.620.70.06` plus its SONAME links. That
library is host-coupled the same way `nvidia-utils`' driver user-space is: NVIDIA's CDI
`create-symlinks` hook points each SONAME at the **newest** versioned copy present in the
container, so an image copy newer than the host's kernel driver wins and NVML/OpenCL init
fails against a module it does not match.

This change drops those three files and makes the strip assert itself. The OpenCL ICD JSON
(`/etc/OpenCL/vendors/nvidia.icd`) STAYS: it names a SONAME (`libnvidia-opencl.so.1`), not
a version, so the CDI-created link satisfies it.

**Why the step lives here and not only in the nvidia candy.** Each installer cleans up
after itself: `nvidia-utils`' driver user-space is installed before this stage and is
stripped by the paired `layer-nvidia` change, while `opencl-nvidia`'s is installed BY this
one. Measured on the cachyos ollama image with the nvidia strip already in place, this was
the last baked driver library left — named by a mount-info probe:

```
$ # in the built image: 34 driver files present, the injected host ones being mounts
baked: /usr/lib/libnvidia-opencl.so.620.70.06
total_driver_files=34 baked=1
```

**Why the enforcement is inside the `run:` and not a `check:` step.** A `check:` step runs
in a container the GPU seam may attach, where the host's libs sit at the SAME paths; the
only way to tell them from baked ones is `/proc/self/mountinfo`, which is not readable on
every venue — a mount-info probe went red on a CORRECT fedora image for that reason. The
`run:` executes in the build container, where nothing has been injected, so a remaining
match is unambiguously image content. It prints the count and fails the build if it is not
zero.

## Change classification

**Breaking change + rollback:** none for charly consumers — at run time the OpenCL driver
library comes from the CDI mount, which is where every GPU pod already gets its driver
user-space, and the ICD JSON that names it is untouched. A consumer that ran this image
WITHOUT CDI would lose OpenCL (not CUDA); no such consumer exists in the org, whose GPU
seams are all CDI-based. Rollback is reverting this commit; the package files return on the
next build, and the assertion in the paired change would then fail loudly rather than
silently — which is the point of putting it there.

Change class: **Candy config** — static `charly box validate`, live `check-ollama-pod` (the
Fedora arm, no regression) with the CachyOS GPU bed supplying the targeted live proof.
