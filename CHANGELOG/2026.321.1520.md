# 2026.321.1520 — fix(pac): strip the driver user-space cuda reinstalls through nvidia-utils

## Summary

fix(pac): strip the driver user-space cuda reinstalls through nvidia-utils

The `cuda` package **depends on `nvidia-utils`** on the pac path, so installing it re-extracts exactly
the host-coupled driver user-space that the nvidia candy's `nvidia-drop-driver-userspace` step had
already removed. The previous step here only dropped `opencl-nvidia`'s share, and its own assertion
(which counts FILES as well as links) therefore passed while the rest of the package's libraries and
its binaries were still in the image.

**Measured, on a real deployment.** A CachyOS `ollama` pod built from today's pins carried
`nvidia-utils 620.70.06-2` against a host kernel module of `615.78.08`. The NVIDIA CDI injection
mounts the host's *versioned* files (`libnvidia-ml.so.615.78.08`, … — 39 paths, verified in
`/proc/self/mountinfo`), while the image's own `libnvidia-ml.so.620.70.06` remained visible, and the
SONAME link resolved to the **newest** file present — the baked one:

```
/usr/lib/libnvidia-ml.so.1 -> libnvidia-ml.so.620.70.06
$ nvidia-smi
Failed to initialize NVML: Driver/library version mismatch
NVML library version: 620.70
(exit 18)
```

and ollama's free-VRAM estimate then yielded nothing usable, so it degraded **silently** to CPU:

```
ggml_cuda_init: found 1 CUDA devices (Total VRAM: 16026 MiB)
load_tensors: offloaded 0/29 layers to GPU
$ charly ollama ps
qwen3:0.6b  989.3 MiB  VRAM 36.0 MiB
```

That is the same failure class as the nvidia candy's strip, one layer down, and it is why the step
must run where the files are actually written. Filed as opencharly/layer-cuda#21.

## What this PR changes

One step, generalized:

- **libraries**: the whole driver user-space — `libnvidia-*.so*`, `libcuda*.so*`, `libnvcuvid*`,
  `libnvoptix*`, `libGLX/EGL/GLES*_nvidia*`, plus `/usr/lib/nvidia`, `/usr/lib/vdpau` and the xorg
  driver — deleted **including the versioned files**, not only the SONAME links.
- **binaries**: the entire `nvidia*` set in `/usr/bin`, `/usr/local/bin`, `/usr/sbin`. A hand-written
  subset is how this step first shipped and its own assertion then caught three leftovers it had
  missed (`nvidia-container-toolkit`, `nvidia-container-runtime.cdi`,
  `nvidia-container-runtime.legacy`); the package also ships `nvidia-ngx-updater`, `nvidia-pcc`,
  `nvidia-powerd` and `nvidia-sleep.sh`. None of them belong in an image: the NVIDIA **container
  toolkit** is host tooling (it generates the CDI spec), and `nvidia-smi` and friends are injected
  per container at the host's version — a baked copy is a second, wrong-version one and, for
  `nvidia-smi`, an actively misleading one.
- **the assertion** covers both sets and counts `-type f` OR `-type l` (the failure class is a
  symlink pointing at a versioned copy) and the versioned files themselves, because the CDI
  `create-symlinks` hook re-creates each SONAME link from whatever versioned file it finds.

What stays image-owned is what a build genuinely needs and CDI does not provide: the CUDA toolkit
under `/opt/cuda` (nvcc, cudart, cudnn, headers, and the **link-time stub** `libcuda.so` under
`/opt/cuda/.../stubs`), cuDNN, onnxruntime.

## How tested

**1. The step enforces itself, at build time, where it cannot be fooled.** This `run:` executes in
the build container, where no CDI has injected anything, so every remaining match is unambiguously
image content — unlike a `check:` step, which may run in a GPU-attached container where the host's
identical libraries sit at the same paths. The step's own counters are asserted `0`, so a future
package that adds another driver file fails the build here instead of shipping.

**2. The image built from this change, inspected**: the `nvidia` image is the box that composes this
candy DIRECTLY, so it is the honest consumer for a pre-merge build:

```
$ charly box build nvidia                # CHARLY_REPO_OVERRIDE at this worktree
$ podman images | grep opencharly/nvidia:2026.321.1448

$ podman run --rm --entrypoint /bin/sh ghcr.io/opencharly/nvidia:2026.321.1448 \
    -c 'ls /usr/lib/libnvidia-*.so* 2>/dev/null | wc -l; ls /usr/bin/nvidia* 2>/dev/null | wc -l'
0        # driver libraries
0        # nvidia binaries
```

and what remains is what a build needs, not what the host must own:

```
$ podman run --rm --entrypoint /bin/sh ghcr.io/opencharly/nvidia:2026.321.1448 -c 'ls /usr/lib/libcuda*'
/usr/lib/libcudadevrt.a
/usr/lib/libcudart_static.a
```

Compare the image built from the previous revision on the same box, which carried the whole driver
user-space (`nvidia-utils 620.70.06-2`, sixteen `nvidia*` binaries).

**3. The GPU still works, and now at the HOST's version.** The same stripped image run with the CDI
device resolves the injected driver:

```
$ podman run --rm --device nvidia.com/gpu=all ghcr.io/opencharly/nvidia:2026.321.1448 \
    -c 'nvidia-smi --query-gpu=driver_version,name --format=csv,noheader; \
        ls -l /usr/lib/libnvidia-ml.so.1; head -1 /proc/driver/nvidia/version'
615.78.08, NVIDIA GeForce RTX 4080 SUPER
/usr/lib/libnvidia-ml.so.1 -> libnvidia-ml.so.615.78.08
NVRM version: NVIDIA UNIX Open Kernel Module for x86_64  615.78.08  Release Build
```

That is the property this PR exists to restore: userspace == kernel module, from the injection only.

**4. The consumer gate, producer-first.** layer-cuda declares no disposable target of its own; the
bed that composes it is `check-cachyos-ollama-pod` / `check-cachyos-comfyui-pod` in
opencharly/distro-cachyos, which can only see this change once its pin advances through
layer-ollama-cuda. Those bumps follow as separate PRs, in that order.

## Change classification

**Breaking change + rollback:** none for a correctly-composed image — the CUDA toolkit, cuDNN and
onnxruntime are untouched, and a GPU container gets its driver user-space from the CDI injection,
which is the only supported source. An image that expected to run without CDI (no injected driver)
would lose its driver libraries, which is the point: that configuration is what produced the
mismatch. Rollback is reverting this commit, restoring the previous narrow strip.

Change class: **Layer (pac package content)** — the step's own build-time assertion, plus the
consumer's `charly box build` and bed.
