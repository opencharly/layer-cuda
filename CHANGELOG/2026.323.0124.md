# 2026.323.0124 — fix(strip): anchor the driver-user-space glob so it stops deleting the CUDA runtime

## Summary

`cuda-drop-driver-userspace` deleted with `-name 'libcuda*.so*'` — a **prefix** glob. The `libcuda` prefix
family is four libraries, and only one of them is the driver:

| name | what it is |
|---|---|
| `libcuda.so`, `libcuda.so.1`, `libcuda.so.615.78.08` | the NVIDIA **driver** user-space |
| `libcudadebugger.so{,.1,.<ver>}` | the driver's CUDA debugger — also injected by CDI |
| `libcudart.so`, `libcudart.so.13`, `libcudart.so.13.5.37`, `libcudart_static.a`, `libcudadevrt.a` | the CUDA **runtime** this layer installs and stitches |

So the step deleted the runtime it had just linked into `/usr/lib64`, and then the layer's own plan check
`ls /usr/lib64/libcudart.so*` exited 2 on every image composing it. Measured on a real built image
(`ghcr.io/opencharly/nvidia-cdi-layer-cuda:check-comfyui-pod-2026.323.0032`, the image the
`check-comfyui-pod` bed runs against):

```
$ podman run --rm --entrypoint /bin/sh <img> -c 'ls -1 /opt/cuda/lib64/libcudart*; ls -1 /usr/lib64/libcudart*'
/opt/cuda/lib64/libcudart.so          # the stitch SOURCE, intact
/opt/cuda/lib64/libcudart.so.13
/opt/cuda/lib64/libcudart.so.13.5.37
/usr/lib64/libcudart_static.a         # the stitched .so family: GONE
/usr/lib64/libcudart_static.a
```

**The fix, and why exactly these names.** The pattern set is anchored (`libcuda.so*`, note the `.`) and
`libcudadebugger.so*` is listed **explicitly**: it is driver user-space but does not carry the
`libcuda.so` stem, so anchoring alone would leave it baked — which `layer-cdi`'s build assertion would then
catch. The evidence that it belongs to the driver set is the CDI spec's own injected `containerPaths` on a
live host, i.e. the same definition `layer-cdi` uses ("patterns == the libs the NVIDIA CDI spec injects"):

```
$ grep -E 'containerPath' /etc/cdi/nvidia.yaml | sed 's/.*containerPath: *//' | grep -E 'libcuda'
/usr/lib/libcudadebugger.so.615.78.08
/usr/lib/libcuda.so.615.78.08
$ ls -1 /usr/lib/libcuda*        # the host's real /usr/lib
libcuda.so  libcuda.so.1  libcuda.so.615.78.08
libcudadebugger.so  libcudadebugger.so.1  libcudadebugger.so.615.78.08
```

The set is defined **once** (`drv=…`) and used by the delete and the residue re-check alike — it was
duplicated before. `set -f` is load-bearing: `$drv` is expanded unquoted into the `find` expression, and
without it the shell would pathname-expand `libcuda.so*` against the *current directory*.

**The step now asserts what it KEEPS, not only what it deletes.** It snapshots every shared library present
before the strip and fails the build naming any CUDA runtime/compute library that disappeared. The residue
count alone cannot tell the two families apart — that is precisely how the runtime came to be deleted while
every build-time control stayed green.

**The `nvidia*` binary strip is deliberately NOT widened.** Three in-tree contracts require a pod image to
carry no `nvidia*` binary: `layer-cdi`'s `cdi-no-baked-driver-binaries` (which fails the build on a non-zero
count, and which states outright that the removal lives here and that its own job is only to prove the
result), `distro-cachyos`'s `comfyui-no-baked-driver` bed check (`! command -v nvidia-ctk`), and `pod-cdi`'s
header ("a pod composes `layer-cdi` and NEVER `layer-nvidia`"). So a pod image that kept `nvidia-ctk` would
break them. What is wrong is that `layer-nvidia`'s checks 4/5 assert `/usr/bin/nvidia-ctk` on an image whose
composition strips it — a plan-scoping question in that repo, filed, not fixed here by leaving the binary in.

## Change classification

Not a Conventional-Commit `!`: no consumer must change its composition or its config, and the layer's
contract — "the driver user-space is not baked, the CUDA runtime is" — is exactly what was broken before.

What a consumer sees: after its pin moves here, a GPU image keeps `libcudart.so*`, so
`ls /usr/lib64/libcudart.so*` goes green. **One consumer must land a companion fix first**:
`layer-cdi`'s `cdi-no-baked-driver-libs` counts with the same prefix glob and would report the surviving
runtime as a leftover driver library (opencharly/layer-cdi#6 — measured: `cdi: driver libraries still baked:
3`, exit 1). That pin bump and that assertion must move together, producer-first.

Rollback: revert this commit. The strip returns to the prefix glob, every composing image again loses its
CUDA runtime, and the cudart check goes back to exit 2 — the pre-fix state, no data or interface to unwind.
