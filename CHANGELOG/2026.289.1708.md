## Summary

**Fixes #12.** The third and last *extension- or root-filtered* loop in this candy's Arch stitch — and this one broke every CUDA **link**.

`nvcc` links the **static** archives by default (`libcudart_static.a`, `libcudadevrt.a`, `libculibos.a`, the `_static` family). The stitch linked libraries with a `*.so*` glob, which **cannot match a `.a`**:

```
cannot find -lcudart_static: No such file or directory
cannot find -lcudadevrt: No such file or directory
collect2: error: ld returned 1 exit status        # --error 0x1 --
```

Nothing was missing from the package: Arch's `extra/cuda` file list contains `opt/cuda/targets/x86_64-linux/lib/libcudart_static.a` and `…/libcudadevrt.a`. The stitch never linked them. Both Arch arms now **enumerate every entry** of the toolkit's lib directories, so `.a` and `.so*` both land:

```sh
mkdir -p /usr/lib64
for libdir in /opt/cuda/targets/x86_64-linux/lib /opt/cuda/lib64; do
  [ -d "$libdir" ] || continue
  for entry in "$libdir"/*; do
    [ -e "$entry" ] || continue
    ln -sfn "$entry" /usr/lib64/"$(basename "$entry")"
  done
done
```

Same defect shape as `#9` — **pattern-matching a directory instead of enumerating it** — one dimension over: `*.h` missed `.hpp` (fixed in `#10`), `*.so*` missed `.a`. With the header loop (`#10`) and the sibling tree (`#11`), the three root-filtered loops are closed.
