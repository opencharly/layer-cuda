# 2026.323.1604 — fix(cuda): walk every lib layout for the driver trees, not one hard-coded /usr/lib

## Summary

`cuda-drop-driver-userspace` removed the `nvidia` / `vdpau` driver trees and the Xorg driver at one hard-coded `rm -rf /usr/lib/...` / `rm -f /usr/lib/xorg/...`. On a distro whose `/usr/lib64` is a REAL directory (Fedora) and on multilib's `/usr/lib32`, those paths stayed baked while the strip printed success — and the `layer-cdi` consumer could not count them without failing a build this step could not make correct.

The removal now walks `$libs` — `/usr/lib`, `/usr/lib32`, `/usr/lib64` — for the driver libraries, the `nvidia`/`vdpau` trees **and** `xorg/modules/drivers/nvidia_drv.so`, from the same ONE definition, and a residue assertion names every surviving tree or Xorg driver and fails the build. The `cuda` skill states the layout-scoped removal and its assertion.

| file | change |
|---|---|
| `charly.yml` | `libs` default gains `/usr/lib32`; the tree/Xorg removal becomes a `$libs` loop; a tree+Xorg residue assertion is added |
| `.agents/skills/cuda/SKILL.md` | the strip section states the three-layout walk and the tree/Xorg assertion |
