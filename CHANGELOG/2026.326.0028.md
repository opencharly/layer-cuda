# 2026.326.0028 — test(cuda): prove the driver strip with a mutation, not by reading it

## Summary

Adds the executable control the driver strip never had (opencharly/layer-cuda#34). The step already asserts what it KEEPS — that is layer-cuda#23's fix — but nothing ran that assertion outside a real image build, and #23 is precisely the case where an over-broad glob looked right in review and deleted the CUDA runtime this layer had just stitched.

`tests/strip-runtime-survives.sh` extracts the step's own shell body from `charly.yml` at run time and EXECUTES it against a synthetic layout, using the override the step already documents for this purpose (`CUDA_STRIP_LIB_DIRS` / `CUDA_STRIP_BIN_DIRS`). Two arms:

- **anchored** — the shipped predicate: `rc=0`, dropped 4 driver files, **deleted 0** runtime/compute libraries, 0 residue, 0 driver trees left;
- **mutation** — the prefix glob (`libcuda*`, layer-cuda#23's regression), one `sed` over the same extracted body: `rc=1`, deleted 2 runtime files and **failed naming `libcudart.so.13` and `libcudart_static.a`**.

Because the body is extracted rather than copied, the fixture cannot drift from the step it judges.

## How tested

```
$ bash tests/strip-runtime-survives.sh
anchored arm (rc=0): … CUDA runtime/compute libraries the strip deleted: 0 (must be 0)
mutation arm (rc=1): … STRIP DELETED A CUDA RUNTIME/COMPUTE LIBRARY: …/libcudart.so.13
strip-runtime-survives: both arms behaved (anchored kept the runtime; the prefix glob failed naming libcudart)
```

Both arms on the committed tree. This is a test-only change: no candy, box, pin or plan step is modified, so no image rebuild is needed to read its result, and the R10 beds for the consumers are untouched by it.
