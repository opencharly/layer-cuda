## Summary

One pin: this candy's `layer-nvidia` ref moves from the `#12` commit to the `#14` commit.

`layer-cuda` pinned `layer-nvidia:054aa7702ebe…` — the `#12` commit. `#12` removed the `stdout:` matcher so the Arch arm could skip honestly, and left the guard that decides whether to skip:

```
if [ ! -e /etc/dnf ] && [ ! -e /etc/yum.repos.d ]; then exit 0; fi
```

That skips only when **both** are absent, while the comment above it states the intent as *"no DNF at all"*. Arch-family arms have no `/etc/dnf`, but `/etc/yum.repos.d` **does** exist there, so the arm fell through to the Fedora assertion and failed. `#14` replaced it with a test for dnf **tooling**, merged, and `tag-on-merge` minted **`v2026.290.2040`** (commit `7766a9d0`). This pins that commit.

**Why the SHA and not the tag.** A SHA ref and a tag ref pointing at the *same* commit are counted as a multi-version disagreement by the resolver — that is why an earlier consumer bump failed with `resolved to multiple git tags with differing content` even though both refs were correct. This candy already used the SHA form, so the advance keeps the **form** identical and only moves the commit. Same form, newer content: no disagreement, and the fix is actually composed.
