# 2026.323.0138 — fix(strip): count the toolkit's static archives in the strip's survival assertion

## Summary

Follow-up to #24, fixing the one non-blocking note its PASS verdict raised: the survival assertion
snapshots `*.so*` and prefix-matches `.so` names (measurement below), so the toolkit's **static archives** —
`libcudart_static.a`, `libcudadevrt.a`, `libcublas_static.a`, … — sat outside the guard. A widened pattern
set could delete them and the build would not name them, which is precisely the failure class the control
exists to catch — measured below, on the merged guard and on this one.

Two changes, both inside the same `run:` step and its own comments:

- the pre-strip snapshot covers shared libraries **and** static archives
  (`\( -name '*.so*' -o -name '*.a' \)`);
- the guard's `case` patterns prefix-match the family names (`libcudart*|libcudadevrt*|libnvrtc*|…`) instead
  of `.so` names, so both halves of the toolkit are inside it.

The deletion predicate is unchanged: `libcuda.so*` plus the explicit `libcudadebugger.so*`, and `libnvidia-*`
and the `lib*_nvidia.so*` family.
