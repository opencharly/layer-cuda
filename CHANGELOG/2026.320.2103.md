# 2026.320.2103 — fix(pins): point the layer-nvidia require at its release tag, not the old commit

## Summary

One line: this candy's `require:` moves from a bare commit pin
(`layer-nvidia:7766a9d06ec5fe8c276c091a68fb72cea12688e3`) to the release tag that carries the
driver-user-space fix, `layer-nvidia:v2026.320.1938` (opencharly/layer-nvidia#22).

**Why it must move.** `layer-cuda` depends on `layer-nvidia`, and that dependency is what
decides which `nvidia` candy a composing image gets. With the SHA pin in place and a box that
names the new tag, the resolver sees the same candy at two refs and refuses the project:

```
$ charly box validate            # in distro-cachyos, after advancing the boxes' pins
charly: error: command "validate": validation error: candy
github.com/opencharly/layer-nvidia resolved to multiple git tags with differing content
within one scope (box=nvidia, box=versa); using newest referenced 7766a9d06ec5fe8c276c091a68fb72cea12688e3
```

So the CachyOS boxes cannot advance to the fix until this pin does. It is also the last SHA pin
in the chain: every other candy ref here is a CalVer tag naming a merged lineage, which is what
the pin contract asks for.
