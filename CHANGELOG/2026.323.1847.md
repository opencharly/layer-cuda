# 2026.323.1847 — docs: the check runner DOES honour exclude_distro; sweep this repo's two copies

## Summary

This repo carried the same false sentence twice — `AGENTS.md` and the
`cuda-arch-header-root` step comment: "the check runner does not honour
runner-level exclude-distro fields". opencharly/layer-nvidia#26 established from
the code that a step-level `exclude_distro:` IS honoured:

- `sdk/kit/planrun.go:181-189` — `RunOne` returns `StatusSkip` when any of the
  IMAGE's distro tags intersects `c.ExcludeDistros`;
- `sdk/kit/planrun_test.go:97` — `TestRunOne_ExcludeDistros` pins it;
- `plugin-check`'s `run_box.go:61,68` and `live_gather.go:220,227` — both gathers
  seed `CheckEnv.Distros` from `meta.Distro`;
- `spec/schema/00_common.cue:217-221` — the field is a shared step-level filter for
  every verb.

Both copies now state the verified semantics. The guard in this step stays, for
the reason the correction leaves standing: the probe's subject (the ARCH header
subtrees are linked) holds by construction on a Fedora image, whose RPMs land in
`/usr` directly, so that arm exits 0 with an honest pass instead of reporting SKIP.
The field filters distro tags; it cannot express "the fact holds trivially here".
The BUILD emitter never reads it, so a `run:` install step's `exclude_distro:` is
inert at image-build time.
