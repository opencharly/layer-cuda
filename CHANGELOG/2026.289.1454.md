# 2026.289.1454 — fix(cuda): link every entry of the CUDA include roots on Arch, not a pattern-matched subset

**Agent:** `dsh-strata`

## Summary

**Fixes #9.** On Arch/CachyOS **every** CUDA build failed — first at CMake's `enable_language(CUDA)` with
`crt/host_config.h: No such file or directory`, and, once that was fixed, `vector_functions.hpp: No such file
or directory` one stage later — while every probe this candy already had kept passing.

One root cause, two signatures. `nvcc` computes its default include root **relative to its own executable**,
and `/usr/bin/nvcc` is a symlink, so every CUDA header must be reachable under `/usr/include`. The Arch stitch
instead enumerated **by pattern**:

```sh
for inc in /opt/cuda/include/*.h /opt/cuda/targets/x86_64-linux/include/*.h; do
  [ -e "$inc" ] && ln -sf "$inc" /usr/include/$(basename "$inc")
done
```

A `*.h` glob links top-level headers. It does **not** match `crt/` or `cccl/` — those are **subtrees** — and it
does **not** match CUDA's `.hpp` half of the `_functions` family (`vector_functions.hpp` and friends).

Both Arch arms now enumerate **every entry** of each include root, linking files of any extension and
subtrees alike:

```sh
for root in /opt/cuda/include /opt/cuda/targets/x86_64-linux/include; do
  [ -d "$root" ] || continue
  for entry in "$root"/*; do
    [ -e "$entry" ] || continue
    ln -sfn "$entry" /usr/include/"$(basename "$entry")"
  done
done
```

No extension list to keep in sync, and no silent drop — which is the point: enumerating by guessed pattern is
what hid this, twice.

Also in this change:

- **A check that can fail** — `cuda-arch-header-root` (build scope) asserts `/usr/include/crt/host_config.h`
  **and** preprocesses a real CUDA translation unit (`nvcc -E -x cu`). Scoped **inside the command**
  (`[ -f /etc/arch-release ] || exit 0`) because this repo's rulebook records that the runner does not honour
  runner-level `exclude-distro` fields, and Fedora's RPMs land in `/usr` directly so its layout genuinely
  differs.
- **The `cuda-skill:` entity mirrored**, per this repo's rule that a behaviour change not mirrored leaves the
  corpus stale — and because the paragraph it corrects was itself the defence's camouflage: it asserted the
  stitch made paths resolve *"identically on Fedora and on Arch/CachyOS"*.
