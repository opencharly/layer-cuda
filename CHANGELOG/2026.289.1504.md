# 2026.289.1504 — fix(cuda): link the toolkit's sibling trees so nvcc can find its backend compiler

**Agent:** `dsh-strata`

## Summary

**Follows `#10` (merged, tagged `v2026.289.1454`), which fixed `#9`.** That fix was correct and incomplete: it repaired the header *files* and *subtrees*, and this PR repairs the toolkit's **sibling trees**, without which no CUDA image can compile at all.

`nvcc` resolves its **own helpers relative to its own executable path**. Through the `/usr/bin/nvcc` symlink, that means `/usr/<sibling>/` — so it looks for its backend compiler at `/usr/nvvm/bin/cicc`, which the stitch never created:

```
CMake Error at CMakeDetetermineCompilerId.cmake:966: Compiling the CUDA compiler
identification source file "CMakeCUDACompilerId.cu" failed.  Compiler: /usr/sbin/nvcc
The output was: 127
  #$ "$CICC_PATH/cicc" --c++20 --static-host-stub ...
  sh: line 1: /usr/sbin/../nvvm/bin/cicc: No such file or directory
  # --error 0x7f --
```

First observed gating a **consumer's** Arch build (`opencharly/layer-strata`, `charly check run check-strata-pod`, run `2026.289.1457`) — i.e. the defect blocks the whole GPU family, not one consumer.

### Two halves, and the second one is the important one

1. **The fix.** Both Arch arms link `/opt/cuda/nvvm` into `/usr/nvvm`, guarded so an existing `/usr` path is never clobbered:

```sh
for tree in nvvm; do
  [ -d "/opt/cuda/$tree" ] && [ ! -e "/usr/$tree" ] && ln -sfn "/opt/cuda/$tree" "/usr/$tree"
done
```

2. **The control — upgraded from preprocessing to compiling.** The check added in `#10` ran `nvcc -E -x cu`, which only preprocesses. **Preprocessing never invokes `cicc`**, so that check stayed **green** straight through this failure. It is now `nvcc -c -x cu -o …`, a real compile that exercises the whole path:

```sh
# before (could not fail on this):
nvcc -E -x cu /tmp/chkcuda.cu > /dev/null
# after:
nvcc -c -x cu -o /tmp/chkcuda.o /tmp/chkcuda.cu
```
